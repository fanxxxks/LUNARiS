# 月序 LUNARIS 4.0 · 可迁移的月面巨构

双击 `月宫华容_三维仿真软件.html`，用支持 WebGL 的 Chrome 或 Edge 打开。最终 HTML 内嵌 Three.js、场景、程序材质、规划器与界面，可离线演示，也可单独复制到其他电脑。观看成品不需要安装 Node.js。

## 场景与空间组织

本版采用五层不规则退台框架，中央空腔贯通；24 个独立房间嵌入骨架，沿水平轨道平移，经框架内部 A / B / C 通道上下迁移。房间与框架之间保留可辨识的尺度关系，界面以三维画面为主，左右窄面板负责任务、选中房间与分层观察。

| 项目 | 当前配置 |
| --- | --- |
| 空间层级 | L1 至 L5，共五层 |
| 可达框架节点 | 42 个；各层为 14 / 11 / 8 / 6 / 3 个 |
| 初始房间数量 | 24 个；各层为 9 / 6 / 5 / 3 / 1 个 |
| 初始调度空位 | 18 个，约占 42.9%；含 14 个升降节点与 4 个普通预留泊位 |
| A · 西侧内核 | 连通 L1 至 L5，独立升降托架 |
| B · 东侧内核 | 连通 L1 至 L4，独立升降托架 |
| C · 后部内核 | 连通 L1 至 L5，独立升降托架 |
| 房间运输包络 | X × Y × Z = 23 × 19.5 × 21 m |
| 泊位中心间距 | X 方向 31 m，Z 方向 30 m；Y 向层距 27 m |
| 五层房间底面标高 | 8.5 / 35.5 / 62.5 / 89.5 / 116.5 m |

“约 43% 调度留白”描述初始空闲节点比例，包含升降通道，并非建筑面积空置率。普通相邻房间的运输包络在 X / Z 方向分别相隔 8 / 9 m；不规则轮廓之外的空白与中央空腔不是可随意停靠的节点。

## 运行一次演示

1. 打开 HTML，等待月面巨构加载。默认显示“科研协作”的初始布局，点击“开始演示”运行。
2. 左侧选择其他任务后，会从统一初始布局重新规划并自动播放。
3. 底部可暂停、继续、重播或拖动时间轴。时间轴显示模拟时间；设置中的 1 / 2 / 4 倍只改变观看速度。
4. 观察底部完成搬运次数、计划搬运距离，以及任务说明中的目标与当前指标。完整搬运包含多个解锁、运输和停靠阶段。
5. 右侧点击 L1—L5 层号单独观察，点击“完整巨构”恢复全景；点击已占用小格或三维房间可切换选中对象。

| 任务 | 实际重构目标 | 结果指标 |
| --- | --- | --- |
| 科研协作 | 将 R02、R03、R08 调入二层实验组，先腾出中转泊位，再完成跨层归集 | 指定协作房间在 L2 的数量从 0 增至 3 |
| 维修隔离 | 将顶层 R24 运到首层东缘检修泊位，腾空两处相邻普通泊位；由 R11 补位顶层 | 检修缓冲泊位从 0 增至 2 |
| 基地扩建 | 启用二层两处预留翼部泊位，迁入已有房间并释放首层物流空间 | L2 入驻房间从 6 增至 8 |

三个任务均使用内部多通道调度，完成后恢复所有升降节点空闲。“基地扩建”保持房间总数为 24，演示已有框架的空间启用；“维修隔离”通过空间留空形成检修缓冲，未模拟气密隔离。

跨层搬运可看到空载托架收拢、升降机构定位、托架展开、泊位解锁、水平转运、Y 轴升降和对接锁定。A / B / C 分别保存托架高度及收拢状态，空载跨层时收拢托架，为途经节点留出空间。当前房间搬运按顺序执行，三个独立托架不表示三个房间同时运输。

## 手动六向调度

点击“手动六向调度”，再选择房间。面板提供 ±X、±Y、±Z 六个方向：

| 操作 | 面板 | 键盘 |
| --- | --- | --- |
| X 方向平移 | −X / +X | A / D |
| Z 方向平移 | −Z / +Z | W / S |
| 降低 / 升高一层 | −Y / +Y | Q / E |

方向按钮移动到相邻可达空位；也可点击右侧任一空闲节点，让规划器寻找通往目标的空闲路径。不会自动搬走挡路的其他房间，需要先手动让位。

灰色方向表示当前正在搬运、急停、目标占用、封闭或轨道边界。普通泊位不能直接穿层，须先进入 A / B / C 升降节点。B 通道最高到 L4，在 L4 的 B 节点不能继续上升。

可按以下步骤体验连续三维移动：

1. 在设置中点击“恢复初始房间布局”，保持通道封闭选项未勾选。
2. 开启手动调度，选择 **R04（L1 · 中01 泊位）**。
3. 点击 **+X**，等待房间进入 **L1 · A 升降通道**。
4. 点击 **+Y** 或按 E，等待底面高度从 **8.5 m** 升至 **35.5 m**。
5. 点击 **−Y** 或按 Q 返回 L1；停靠后点击 **−X** 回到原泊位。

每次搬运完成后才能发下一条指令。演示途中进入手动模式，会先完成当前房间的停靠，再保留已经形成的布局与三个托架的位置；不会突然把运输中的房间还原。切换预设任务会重新使用统一初始布局。

## 通道封闭、暂停与急停

设置中的“封闭 L2 · C 通道”会将该节点加入路径禁用列表。

- 在预设任务中切换封闭状态，会恢复初始布局、重新验证计划并暂停，点击播放观察结果。
- 对“科研协作”启用封闭，可观察原本经 C 通道的相关搬运改由 B 通道绕行，仍达到同一任务目标。
- 手动调度继续使用当前布局检查可达性。如果正在搬运的路径经过 L2 · C，界面会拒绝此时封闭，要求停靠后再操作。
- 普通暂停保留当前时间与位置，拖动时间轴可检查升降中间状态，也可反向回看。
- “模拟急停”停止搬运并锁定时间轴；房间保持当前位置。点击“解除急停”后继续，不重置布局。
- 切换浏览器标签页会暂停播放；回到页面后可手动继续。

## 镜头、材质与光照

左键拖动环视，右键或 Shift 拖动平移，滚轮缩放；触屏使用双指缩放与平移。观察栏提供全景、房间近景、俯视、立面、框架透视和自由漫游。

**框架透视**暂停搬运并隐藏房间，显示原位承重框架、水平轨道及内部升降机构；不会把楼层炸开，也不会改变实际层距或调度坐标。切换其他视角恢复房间，点击播放会返回正常全景。

**自由漫游**使用 WASD 移动、Q / E 改变高度、Shift 加速，拖动转向，滚轮前后移动。进入漫游会退出手动调度；它是相机观察工具，不计算相机与房间的碰撞。Esc 可退出漫游、关闭设置或退出沉浸展示。

“沉浸展示”收起顶部与两侧面板，保留场景观察和底部播放控制。手机布局将房间控制放在三维画面下方，可向下滚动操作。

渲染内容包括：

- 离线生成的 HDR 反射环境，PBR 金属、舱体、粗糙度及拉丝程序纹理。
- 透明玻璃与舱内立体物体、照明、不同用途的房间外观和设备。
- 桁架连接、水平导轨、维护步道、升降托架、基础与辅助设施。
- 月面起伏、陨石坑、岩石、地表颗粒、太阳能设施、通信与巡视设备。
- 方向光阴影、电影式色调映射；精细模式叠加基于深度的环境遮蔽、辉光与抗锯齿处理。

| 设置 | 效果 |
| --- | --- |
| 精细画质 | 4096 × 4096 阴影贴图，较高像素比与完整后处理 |
| 均衡画质 | 2048 × 2048 阴影贴图，降低像素比并简化后处理，保留材质与阴影 |
| 晨光 | 暖阳、冷影与舱内照明的对比 |
| 白昼 | 提高结构与表面细节的可读性 |
| 夜景 | 降低环境光，突出舱内灯光和基地设施照明 |
| 曝光 | 调整整体明暗 |
| 标注 / 轨迹 | 控制房间标签与当前搬运路径显示 |
| 镜头跟随 | 播放时跟随当前运输房间 |
| 循环演示 | 完成预设任务后从头播放 |

FPS、当前画质和计划中的累计垂直行程位于设置面板。帧率取决于显卡、显示尺寸与浏览器；画面不流畅时切换均衡画质。页面提示 WebGL 上下文丢失时，刷新可重新构建场景。

## 仿真坐标与边界

采用 X 水平、Y 竖直、Z 纵深。房间坐标对应底面锚点，1 个场景单位 = 0.25 m。源码中的运输包络为 92 × 78 × 84 场景单位，X / Y / Z 泊位间距为 124 / 108 / 120；导出记录写明换算比例。

规划器在不规则三维邻接图上搜索，只有同层相邻轨道或同一内部升降通道的相邻层具有连接。每段搬运沿单一坐标轴移动，使用连续扫掠 AABB 检查与其他房间的运输包络分离，并保留 3 个场景单位、即 0.75 m 的检查余量。运动逐段平滑加减速；布局在停靠完成后更新，拖动时间轴可以确定性回放。

本软件验证空间可达、房间占位、运动包络和动作时序。框架、驱动、锁定、接口及月面环境是建筑方案表达，未完成承重、动力、稳定性、气密、月尘、辐射和热环境工程计算。原 800 × 600 mm 平面样机与这里的大型建筑尺度分别验证；场景速度、尺寸和影像不能直接作为施工或电机选型依据。

## 导出记录与源码

设置中的“导出三维仿真记录”下载 `LUNARIS-XYZ-simulation.json`，记录包括：

- 4.0 版本、坐标系、单位换算与场景配置；
- 42 个节点、泊位坐标、三条升降通道及当前计划的起始布局；
- 三个托架的初始状态、房间路径、动作阶段和预测模拟时长；
- 任务目标、当前三维状态、时间、封闭节点与操作事件。

手动模式的 `moves` / `phases` 表示当前一次搬运；之前已经发出的手动指令保留在 `events` 中。导出是记录文件，不包含导入恢复功能。

| 文件 | 作用 |
| --- | --- |
| `月宫华容_三维仿真软件.html` | 可独立离线运行的最终成品 |
| `simulation-core.js` | 三维节点、邻接、路径、扫掠检查、任务与独立托架时序 |
| `lunar-scene.js` | 房间、巨构、月面、程序材质与渲染 |
| `lunar-app.js` | 交互、镜头、播放、手动调度、设置及记录导出 |
| `lunar-ui.html` | 响应式界面与脚本插入占位符 |
| `vendor/three.min.js` | 本地 Three.js r160 |
| `build-simulation.cjs` | 检查脚本语法并打包独立 HTML |
| `simulation-test.cjs` | 核心拓扑、任务、连续运动与随机调度检查 |
| `lunar-validation.cjs` | HTML、实际 Three.js 几何和应用交互的集成检查 |
| `框架方案设计说明.md` | 空间组织与概念方案说明 |

`simulation-ui.html`、`simulation-app.js` 为历史版本，不参与当前构建。重建时编辑当前源码；直接修改成品 HTML 会在下次构建时被覆盖。

## 构建与验证方法

源码构建和自动检查需要可用的 Node.js，不需要联网安装 npm 包。在项目目录打开 PowerShell，依次执行：

```powershell
node build-simulation.cjs
node simulation-test.cjs
node lunar-validation.cjs
```

构建脚本依据自身目录读取源码，即使从其他工作目录调用，也会把成品写回项目目录；集成检查读取当前目录下的 HTML，因此上述验证命令应在项目目录运行。修改源码后先重新构建，确保集成检查读取最新成品。

核心检查覆盖 24 个房间、42 个节点、五层不规则拓扑、中央空腔、三个内部通道、三项任务目标、连续扫掠、房间守恒、托架状态连续性、继承托架位置、封闭通道改路、确定性时间轴，以及 1,000 次可复现合法随机移动。

集成检查使用实际 Three.js 几何，但模拟 GPU 与 DOM；用于核对脚本初始化、房间包络、任务播放、暂停、时间轴末端、急停、手动 X/Y 调度、五层地图、框架透视、沉浸、光照、画质、漫游、封闭改路与 JSON 导出。它不能证明真实显卡渲染或屏幕排版正确。

真实浏览器验收应另外执行：

1. 在 1440 × 900、1280 × 720 和约 375 px 手机宽度观察全景、任务、楼层地图与手动控制，检查遮挡和滚动。
2. 播放三项任务至结束，核对各自结果指标及升降通道恢复空闲。
3. 按上述 R04 示例执行 +X、+Y、−Y、−X，暂停在升降途中，确认位置连续。
4. 来回拖动时间轴，并拖至末端，确认房间停靠后可继续手动操作。
5. 封闭 L2 · C，运行科研协作，观察绕行与相同任务结果。
6. 检查框架透视保持原层距，切回全景后房间恢复；测试漫游、分层和沉浸。
7. 切换三种光照与两种画质，近看玻璃、室内、金属、阴影及轨道细节；查看浏览器控制台是否有错误。
8. 导出 JSON，核对版本 4.0、42 个节点、24 个房间和 3 条升降通道。

自动脚本的 PASS 输出与真实浏览器验收分别记录，以当前构建结果为准。
