# 使用与维护

## 启动

Windows 双击 `启动高性能仿真.cmd`：启动器自动运行本机 Node.js 服务，打开 `http://127.0.0.1:8787`，使用独立浏览器配置启动 Edge 或 Chrome 并请求高性能 GPU。需安装 Node.js 20+；也可运行 `npm start` 后打开该地址。已有同项目服务会被复用；端口冲突时设置环境变量 `LUNARIS_PORT` 后重新启动。

直接打开根目录的 `月宫华容_三维仿真软件.html` 仍可离线演示；它内嵌 Three.js、规划器、模型、材质与字体。离线方式支持原有类型直线调度；大模型分层与模糊指令需要通过本机服务启动并联网。

默认跟随显示器刷新率；实际速度取决于设备与浏览器。基本设置中的渲染状态用于查看实际 GPU 和帧时间，启动参数不保证系统一定选择独显。

## 操作

- 典型任务包括科研协作、维修隔离和基地扩建；选中任务后自动播放，任务条目悬停或键盘聚焦时显示目标和意义。
- 自然语言调度使用当前停靠布局。输入框以占位文字显示示例；执行生成真实搬运路线，重置仅清空输入。也可按 Ctrl / Command + Enter 提交。
- 手动调度先选房间，再点击黄色「＋」泊位搬运；成功开始搬运后侧栏保持展开。关闭手动面板恢复全景和全部楼层，保留搬运计划与布局。
- 房间图鉴保留在侧栏，可选择八类房间并切换完整外观、下层内饰和上层内饰。
- 图鉴切换采用约 1.25 秒的点云分解、线束过渡与实体聚合，并以细圆环、刻度和辅助线作为背景；切换保持观察角度与缩放。连续点选采用最后一次选择，拖动模型时立即完成切换。系统启用「减少动态效果」时直接切换，静止后停止动画渲染。
- 普通视图中拖动旋转、右键拖动平移、滚轮缩放；全景可恢复全部楼层。
- 自由漫游使用 WASD 平移、Q/E 升降、Shift 加速；滚轮调整移动速度，范围 0.1×–8×。
- 播放栏支持暂停、重播、进度拖动与倍速。搬运透视显示活动房间的包络边框与步骤提示。
- 基本设置提供画质、光照、抗锯齿、帧率选择、导出、急停、通道封闭和恢复初始布局。

## 自然语言范围

在线调度使用并行科技 `https://llmapi.paratera.com/v1` 的 `GLM-5.3`。支持按 R01–R24 编号或材料、生命、居住、能源、物资、通信六类功能选房间。模型只输出空间目标；后台 Worker 根据当前布局生成实际搬运步骤，逐步校验占位、通道、碰撞、锁定房间和最终目标。

| 难度 | 可直接输入的例子 |
| --- | --- |
| 简单排列 | 让 R01、R02、R03 按顺序排成一列 |
| 整类分层 | 把所有科研房间放在下层 |
| 模糊组合 | 科研集中协作，居住远离能源，尽量少搬运 |
| 保持条件 | 把 R19 放到 L2，保持 R01 不动 |

“科研”按仿真功能分类包含全部 8 个材料实验与生命科学房间；“下层”默认 L1–L2。集中协作解释为同层并偏好紧凑，不能据此保证舱口全部连通。远离能源默认两组房间的网格曼哈顿距离至少 2，即列差、行差、楼层差绝对值之和；这只表达空间间隔，不是噪声模拟。界面会显示模糊词的具体解释。明确给出的编号、数量、顺序、楼层和保持条件进入约束；无明确对象或无法建模的要求会要求补充。

排列支持同层 X / Z 方向 2–5 个房间；分层、集中、靠近、分离可组合最多 6 项目标，可锁定房间完全不搬运。受泊位容量与连通性限制，不保证任意组合都能实现，也不保证全局最少搬运次数。模型请求最多等待 75 秒，规划搜索最多约 22 秒。搬运中或急停时不能提交；请求失败、校验不通过或计算期间场景变化时保留原计划。

## 模型配置

模型配置文件位于项目根目录的 `llm-config.json`，与启动脚本同级，随仓库保存。服务直接读取该文件，不再读取 `%LOCALAPPDATA%` 中的旧配置。结构如下（文档使用占位密钥）：

```json
{
  "apiKey": "你的平台密钥",
  "baseUrl": "https://llmapi.paratera.com/v1"
}
```

也可通过环境变量 `LUNARIS_API_KEY`、`LUNARIS_BASE_URL` 配置，环境变量优先。模型固定为平台的 `GLM-5.3`，使用 low 思考级别。仓库中的密钥仅由本机服务读取，浏览器请求、HTML 和导出文件均不含密钥。发送到模型的是输入指令、房间功能和当前泊位/封闭状态。服务只监听 127.0.0.1，并校验来源与当前页面会话。

首次配置后刷新页面即可；更改服务端代码或环境变量时需停止旧服务再重新启动。网页直接以文件方式打开时不会调用模型。界面显示网络、鉴权或额度错误时按对应信息处理，不会静默切换其它模型。

## 模型与材质

当前模型为 24 个房间、42 个节点、5 层空间，单舱外形约 11.5 × 10.5 m。八种视觉模型覆盖居住、生命支持、能源、生物培养、医疗、工程工坊、服务器和指挥舱。内饰、透明窗、设备与舱口为真实三维几何，保留本地建模和实例合批优化。

房间外壳、屋顶、舱门和服务面板采用细凹凸银色金属：细密浅纹理叠加大尺度舒缓起伏，让亮部和暗部以宽幅区域柔和过渡。法线贴图分别控制细颗粒与整体起伏，不增加真实位移或改变搬运包络。框架、窗框和内饰继续使用拉丝与磨砂金属，便于区分结构。反射环境仅在启动时生成，贴图共享，不增加逐帧环境捕捉。

材质图册位于 `assets/textures/index.html`，需连同该目录一起复制，现有 18 类材质。`source/` 保存原图，`pbr/` 保存各材质通道，`gallery/` 保存图册引用的内景图片；图册中的截图是静态素材，不随程序构建自动更新。

| 通道 | 数据含义 |
| --- | --- |
| albedo | sRGB 颜色，外壳 2048 × 2048，其余 1024 × 1024 |
| normal | OpenGL +Y 切线空间法线，线性数据 |
| orm | R：环境遮蔽；G：粗糙度；B：金属度 |
| roughness / metalness | 对应 ORM 的独立通道，便于查看与复用 |
| height | 推导的微表面起伏；当前不用于几何位移 |

外壳细凹凸银色金属的颜色、法线、ORM 和高度等通道均为原生 2048 × 2048，由程序在目标分辨率直接采样，法线像素数为原先 512 × 512 的 16 倍；其余材质的数据通道为 512 × 512。外壳采用最高 16 倍各向异性过滤（受硬件上限约束），并共享贴图与 mipmap。多数材质原图由 ImageGen 生成；细凹凸银色金属使用程序生成的周期高度场：大尺度起伏与细密浅颗粒分别控制，颜色保持近乎均匀的银色，避免把频繁交替的明暗烘焙进贴图。轻磨砂拉丝银合金由 `build-textures.cjs` 中的固定种子定向纹理生成，颜色保留轻微丝纹和磨砂颗粒，法线只表达浅微起伏，高光来自实时反射。表面参数为图像推导或程序生成与人工标定的近似，不是实测扫描。玻璃原图保留透明通道，玻璃预览底色不代表实际透光效果。

## 字体与依赖

中文标题使用 Source Han Serif SC Bold 的子集 Lunaris Serif；英文字体提供 Space Grotesk 子集 Lunaris Display。构建会优先查找本机 Novecento Wide Bold；也可将有授权的 `novecento-wide-bold.woff2` 放到 `vendor/fonts/` 后重新构建。未提供该文件时使用嵌入的 Space Grotesk 回退。

字体源文件、OFL 许可和子集覆盖报告均保存在 `vendor/fonts/`。HTML 构建只需 Node.js；材质重建依赖 `package-lock.json` 中的 sharp；字体重建依赖 `requirements.txt`。

## 背景音乐

背景音乐《Flow of Life》原文件保存在 assets/audio/flow-of-life.mp3，构建时原样内嵌到 HTML，离线可播放。首次点击或按键后循环播放，默认音量 18%；“循环背景音乐”“音乐静音”和音乐音量独立保存。暂停建筑演示不会暂停音乐，切换后台时暂停，返回后从原位置继续。

在“基本设置 → 背景音乐”使用“恢复音乐”重试播放；它会解除音乐静音，并在音量为零时恢复到 18%，不会重置歌曲进度。本分支仅包含背景音乐，不包含机械或操作提示音。

验证：node scripts/check-background-music.cjs，报告位于 docs/audio-validation/music-report.json。

## 维护流程

1. 在 `src/` 修改源码。文件关系和闭包拼接约束见上级 [README](../README.md)。
2. 文案变化后运行 `npm run build:fonts`；材质源图或参数变化后运行 `npm run build:textures`。
3. 运行 `npm run build`，检查模板标记、脚本语法与 Worker 语法并生成 HTML。
4. 在浏览器中检查三个任务、自然语言计划、手动点选、跨层升降、暂停与急停、关闭面板、漫游调速和导出。
5. 检查透明窗、双层内饰、六向连接、人流热图，以及桌面和窄屏布局。运行性能检测时记录分辨率、画质和实际设备。

不直接修改成品 HTML 或 `src/generated/texture-pack.js`。历史测试脚本、一次性修订脚本、验收截图、重复交付包和旧字体缓存已清理；构建命令及人工检查步骤统一在此维护。

## 方案边界

软件表达几何、占位、时序、六向连接和假设人流，不替代载荷、强度、气密、驱动、热控或载人安全论证。人流按最短路分配，不模拟拥堵；播放倍速不改变模型时长。

`方案/` 中保留正式 Markdown 和历史 V4/V5 Word，原 8 舱 XY 样机、推进器母港方案与当前内部 XYZ 搬运版本有不同假设。讲解当前仿真时以当前源码与界面为准。
