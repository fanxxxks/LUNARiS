# 月序 LUNARIS 7.0 · 空间重构工作台

双击 `月宫华容_三维仿真软件.html`，用支持 WebGL 的 Chrome 或 Edge 打开。成品内嵌场景、程序材质、规划器、交互和 Three.js，可离线运行，也可单独复制到其他电脑。观看成品无需安装 Node.js。

## 2026-09-08 · 左侧收纳导航与自然语言调度

界面参考终末地的白色侧栏、灰黑几何图标与展开菜单。默认保留窄图标栏，鼠标进入左侧展开，离开菜单区域后自动收回。点击顶部菜单按钮可固定展开，再点收起；键盘聚焦与文字输入时保持展开，触屏可直接点击入口。

- 「典型任务」：科研协作、维修隔离、基地扩建统一收进一个入口，选择后自动播放。
- 「自然语言调度」：输入模块连接目标，生成并自动执行真实搬运路线。输入框已预填示例，可直接修改或执行，也可按 Ctrl / Command + Enter 提交。
- 「视图切换」：全景、近景、俯视、立面、框架透视、自由漫游、人流热力与舱内剖切。
- 「手动调度」：五层索引、房间详情和手动六向调度。点击三维房间也会打开。
- 「基本设置」：画质、光照、性能检测、导出、急停、封闭通道、恢复初始布局等。
- 「沉浸展示」：收起导航与播放栏，保留搬运提示和透视开关。

搬运时，淡绿色简洁包络边框透过其它房间显示当前房间位置；右下角「搬运透视」小滑动开关控制这层边框。指向房间的气泡显示房间名称、当前步骤、搬运序号和暂停 / 急停状态。气泡随镜头与房间位置更新，房间出画面后隐藏。

### 精简界面与悬停反馈

导航仅显示图标与功能名，移除数量统计、英文副标题、宣传语和常驻操作提示。任务菜单仅保留三张任务按钮，自然语言菜单仅保留预填示例的输入框、执行和必要结果状态。

侧栏与二级菜单止于底部播放栏上方，因此展开导航也能直接使用开始 / 再次演示、重播与进度条。普通按钮悬停显示亮黄边框，主操作显示明黄色底色，图标仅上浮放大、不旋转；键盘聚焦提供同等反馈，减少动态效果的系统偏好会关闭浮动动画。

### 自然语言指令范围

本版为离线中文规则解析与约束规划，不调用外部大模型。支持六类现有模块：材料、生命、居住、能源、物资、通信，按输入顺序排列为同层连续直线，目标限定在普通泊位。支持 2–5 个模块，可指定 L1–L5 或中文楼层，以及 X / Z 方向（默认 X 正方向）；能否安排取决于该楼层的连续泊位、模块数量与可达性。

示例：

- 构建一条直线相连的居住模块、材料模块、通信模块
- 在一层沿 X 方向将能源、物资、通信模块直线相连
- L1 沿 Z 方向将材料、生命、居住直线相连
- 居住、居住、通信直线相连

调度使用当前已停靠布局，自动选择对应房间，允许其它房间搬移让路，也允许临时停靠升降节点；最终清空升降通道。所有移动都经过现有路径与连续碰撞检查，沿导轨 / 升降机构播放，完成后持续高亮目标模块。已满足目标时直接高亮，不进行多余搬运。

不支持的模块、否定或锁定条件、环形 / 分支 / 跨层排列会明确提示，避免忽略条件执行。复杂布局采用有时间上限的搜索，不保证最短路线或找到所有可行解；失败时不改变场景。正在搬运或急停时不会接受新计划；请先完成当前计划或恢复初始布局。后台计算期间场景发生变化时，本次计算结果作废，需重新提交。

界面由 `lunar-ui.html`、`lunar-style.css`、`lunar-app.js` 维护；规划器为 `lunar-scheduler.js`。运行 `node build-simulation.cjs` 生成包含后台规划线程的独立 HTML，可直接离线打开。修改文字后可先运行 `python build-fonts.py` 更新内嵌字体子集。

验证命令：`node lunar-scheduler-test.cjs`、`node lunar-interaction-test.cjs`、`node lunar-validation.cjs`。其中交互 / 集成检查使用真实 Three.js 几何与模拟 DOM / GPU，实际画面另在浏览器检查。

第七版保留紧凑的积木式房间堆叠，并新增六面舱口、相邻气密短接的几何表达和模拟人流热图。24 个房间沿五层不规则轮廓组合，形成错层退台、局部悬挑和留空；精简框架藏在楼板与接缝中，A / B / C 三条内部通道承担升降。画面以房间组团为主体，落位后由框架支承并锁定。

| 项目 | V7 配置 |
| --- | --- |
| 空间层级 | L1 至 L5，共 5 层 |
| 有效节点 | 42 个，各层为 14 / 11 / 8 / 6 / 3 个 |
| 初始房间 | 24 个，各层为 9 / 6 / 5 / 3 / 1 个 |

| 相邻外包络净距 | X / Y / Z = 1.0 / 1.4 / 1.2 m，概念几何尺寸 |
| 房间底面标高 | 3.4 / 12.6 / 21.8 / 31.0 / 40.2 m |

| 升降通道 | A、C 连通 L1—L5；B 连通 L1—L4 |

## 快速演示

1. 打开 HTML，等待月面聚落加载。初始为“科研协作”已就绪状态，点击底部“开始演示”。
2. 底部主栏直接选择 **1× / 2× / 4× / 8× / 16×**，默认 **4×**。倍速只改变观看速度，不改变目标布局或房间尺度。
3. 点击播放按钮暂停或继续；“重播”从当前计划开头播放。拖动时间轴会暂停并显示所选模拟时刻。观察载荷交接时可使用 1×。
4. 左侧切换预设任务会恢复统一初始布局、重新规划并自动播放。底部显示当前动作、完成搬运次数和计划搬运距离。
5. 右侧点击层号单独观察；再次点击同一层或“完整聚落”恢复全部楼层。点击已占用格位或三维房间可选中对象。

“基本设置”中可启用循环演示和镜头跟随搬运。切换到后台标签页会暂停，返回后可手动继续。“模拟急停”冻结软件状态，点击底部“解除急停”继续；它没有模拟真实设备的断电制动或故障恢复控制。

## 三个预设任务

| 任务 | 搬运次数 | 可核对的终态 |
| --- | --- | --- |
| 科研协作 | 6 次 | R02、R03、R08 归集至 L2，二层协作房间由 0 增至 3，升降节点恢复空闲 |
| 维修隔离 | 6 次 | R24 从顶层移至首层东缘检修位，两处相邻普通位留空；R11 补入顶层 |
| 基地扩建 | 9 次 | 启用 L2 两处预留位，二层入驻由 6 增至 8；全站仍为 24 个房间 |

搬运包括必要的让位和中转，因此一次任务的搬运次数可能多于目标房间数。观察升降机构的收拢、空载换层、展开、房间解锁、水平平移、带载升降与落位锁定。程序按相邻节点、当前占位和扫掠包络检查路径；一次只有一个房间执行搬运。

“维修隔离”的缓冲表示空间留空，没有完成气密或污染隔离验证。“基地扩建”表示重组现有房间与启用预留位置，没有新增房间实体。

## 手动操作：选房间，立即搬运

左侧入口依次为「典型任务」「自然语言调度」「手动调度」「视图切换」「基本设置」。典型任务分别显示为科研协作案例、维修隔离案例、基地扩建案例。

1. 打开「手动调度」即进入手动模式。若正在演示，会先完成当前房间停靠，然后保留布局切换；急停时需先恢复播放。
2. 在 L1–L5 标签中切换楼层，点击房间编号选择房间，也可直接点击三维房间。上方卡片即时显示已选房间与位置。
3. 黄色空位表示当前房间可达的位置，点击后立即开始搬运；也可使用左移、右移、前移、后移、升层、降层按钮。升降只能发生在内部升降通道。
4. 运输期间方向按钮和空位禁用，房间卡片显示「搬运中」；停靠后恢复操作。点击「房间详情」可查看模型、尺寸与连接信息。

示例：初始布局选 L1 的 R02，再切换 L2，点击后04 空位，即可自动执行跨层转运，底面由 3.4 m 升至 12.6 m。无需二次确认。

已占用、封闭或不可达的目标不会执行。手动调度不会自动移动其它房间让路，需要先腾出通路；典型任务会恢复各自的初始布局。

倍速使用页面内的深色菜单，提供 1×、2×、4×、8×、16×，不再依赖原生弹层。方向键切换选项，Enter 确认，Esc 收起。搬运透视开关采用浅色底和亮黄选中态，与导航配色一致。

## 六面舱口与相邻连接

每个房间具有 +X、−X、+Y、−Y、+Z、−Z 六个接口。选中房间后，检查器显示已连接接口数量和方向；在“基本设置”中切换“显示六向连接”可控制短接结构的显示。

短接只建立在**正交相邻、已占用且当前可通行**的两个房间之间。水平连接跨越相邻房间接缝，竖向连接对齐上下舱口，舱内公共前室与竖向梯补足内部路线；空泊位、中央留空和空货运井不会被当作人员捷径。短接有空心通道、壁体、框架和可收回的舱门几何，属于气密连接的概念表达，未模拟气压、检漏或真实密封性能。

搬运前关闭舱门、隔离服务并收回短接；移动中的房间退出人员图。落位时依次恢复短接、服务和舱门，完成后重新参与通行。A / B / C 的房间货运机构与这张人员连接图分别计算。

## 使用模拟人流热图

1. 点击“人流热力”，在右侧分析卡选择“日常通勤”“科研协作”或“应急集合”。
2. 调整需求强度，范围为 **0—300 人次/分钟**，默认 **120 人次/分钟**。它是输入假设，不是传感器测得的在场人数。
3. 比较舱内连续色场、连接处热度及方向粒子。颜色从少到多表达相同需求设定下的分配强弱；粒子用于提示方向，不是一粒代表一名真实人员。
4. 读取“通行人次 / min”“峰值 / min”“可用连接”和“未连通需求”。通行人次是成功分配到可达路径的需求，峰值是单条短接上的最大流量；未连通需求单列，不转分给其他房间。
5. 在搬运前后或不同任务终态使用相同场景、相同需求比较。房间移动、落位或连通关系改变时，分配自动更新。

| 场景 | 当前需求假设 |
| --- | --- |
| 日常通勤 | 居住舱到工作舱；按实验、能源通信和物流用途设置目标权重 |
| 科研协作 | 实验舱互访，以及实验与物流舱之间的加权往来 |
| 应急集合 | 非居住舱到居住舱的等权集合需求，不模拟出口、排队或疏散容量 |

初始布局的人员网络有 **3 个连通分量**：21 个房间组成主组团，R03 独立，R17 与 R22 组成另一组团。因此初态并非全站互通；分析卡会保留相应的不可达需求。可用连接数统计实际相邻短接，与 42 个搬运节点不是同一指标。

模型按给定起终点需求在当前可用网络中分配最短路径，不模拟容量约束、排队、拥堵反馈、避让或个体行为。它用于讨论空间组织，不能直接推断实际人流、舒适度或疏散时间。

## 检查封闭通道

勾选“封闭 L2 · C 升降通道”，重新选择“科研协作”。当前规划可通过 A / B 通道完成同一科研终态，应观察到路径改变，而不是穿过封闭节点。取消封闭后可重新生成原条件下的计划。

其他布局下，封闭或房间阻挡可能造成无可用路径，界面会说明原因。正在搬运时先完成落位，再修改影响当前路径的封闭条件。

## 画质、抗锯齿与性能检测

左侧“基本设置”提供三档质量，默认**精细**。晨光、白昼、夜景与曝光调节可独立使用；拖动镜头不会自动更改所选档位。

| 质量档位 | 当前渲染取向 |
| --- | --- |
| 精细（默认） | 保留精细模型和材质、4096 阴影、半分辨率环境遮蔽与辉光，兼顾观察和交互 |
| 极致 | 提高像素密度与环境遮蔽采样，保留 4096 阴影；画面静止后渐进积累 8 帧，改善边缘和细小结构 |
| 高帧 | 保留房间几何及材质细节，降低像素密度和阴影分辨率至 2048，省去环境遮蔽采样以减少渲染开销 |

抗锯齿可选“自动选择”“MSAA”“FXAA”。自动模式在设备支持时使用离屏多重采样，并配合 FXAA；MSAA 模式优先多重采样，在不支持时回退 FXAA；FXAA 模式使用后处理边缘平滑。实际 MSAA 采样数取决于当前质量档位和设备能力，主界面的质量状态显示当前结果。

极致档的 **8 帧静态积累**不是 8 倍播放，也不是将运动画面混合。相机、搬运或人流粒子仍在运动时采用即时绘制；停止后重新积累，完成即停止持续刷新。要观察静态精修，可暂停搬运、关闭人流热力并停止操作镜头。

目标帧率可选 **30 / 60 / 120 FPS**，默认 **60 FPS**。该选项设置绘制调度目标，不保证设备达到该数值；显示器刷新率、浏览器、窗口尺寸和当前画质都会影响结果。调低目标帧率不改变模拟距离、任务终态或所选播放倍速。

点击底部“性能检测”，程序暂停搬运并切回全景，自动旋转镜头：**约 1 秒预热，再采样 8 秒，共约 9 秒**。完成后显示该设置下的平均 FPS、P95 帧间隔和样本帧数；检测中再次点击可停止。比较画质时应固定窗口尺寸、目标帧率和场景条件，并保持页面处于前台。

底部 FPS、P95 帧耗时、draw / tri（绘制次数 / 三角形数）是当前浏览器的运行参考。帧耗时来自帧间隔统计，不是单独的 GPU 着色器计时；静止时可能保留最近样本。按需重绘、状态缓存和局部实例更新减少重复工作，本说明不预设任何实测帧率。

## 导出记录与验证边界

点击“导出三维仿真记录”下载 `LUNARIS-XYZ-simulation.json`，内部版本为 **7.0**。记录包含配置、初始布局、42 个节点、A / B / C 升降通道、任务、路径、动作时序、操作事件、封闭节点和当前状态，并包含人流分配结果与画质、抗锯齿、目标帧率设置。

位置使用场景单位，换算米时乘以 `metresPerSceneUnit = 0.1`。当前状态中的升降机构高度与收拢程度用于还原机械搬运动画；搬运距离和模拟时长也属于当前参数下的结果。界面提供导出，没有记录导入按钮。

本版检查几何、连通、占位、扫掠包络及搬运动作时序。机械承载、升降驱动力、断电制动、锁定保持、气密接口、防尘热控与月面环境仍需独立计算和试验。原 800 × 600 mm 二维磁牵引样机只能支持对应的平面原理验证，不能证明建筑尺度的载人多层搬运已经可行。

修改源码后，需要重新构建 HTML 才能在成品中看到改动。旧 V4、V5 方案文档保留作历史对照；其中尺度、形态与运动架构不代表当前第七版。`simulation-app.js` 与 `simulation-ui.html` 不属于当前构建入口。

在项目目录使用 Node.js 执行：

```powershell
node build-simulation.cjs
node simulation-test.cjs
node lunar-validation.cjs
node .codex-review/v7-performance-test.cjs
```

核心检查覆盖 V7 规划、占位、扫掠、时序、任务终态和六向人员图；集成检查覆盖打包成品与界面联动；性能脚本检查按需重绘、相机输入、局部更新、倍速、质量切换及静态精修。集成与性能检查使用 GPU 替身，不证明真实设备的画质或帧率。

维护界面文本时，可按 `vendor/fonts/README.md` 运行 `python build-fonts.py` 更新字体覆盖，再运行 HTML 构建。重建字体需要 `fonttools` 和 `brotli`；复用已提供的 WOFF2 字体打包 HTML 仍只需 Node.js。

构建后在浏览器逐项查看三个任务终态、R02 手动即时搬运、五层地图、内部升降、六面舱口开闭、短接收回与恢复、剖切及封闭改道。再比较三种人流场景、0 与 120 人次/分钟需求、不可达需求记录、三档质量、抗锯齿选择、极致静态精修及 9 秒镜头基准；桌面与手机布局分别检查。

近景观察时点击“全景”恢复全部楼层。点击播放也会恢复全景继续转运；剖切按钮保持独立开关。若只是修改源码后的快速检查，可运行 `node lunar-validation.cjs --source`；最终仍需重新构建并检查成品。
